# Idea → 最小 pilot

执行入口：[aeons-idea-workflow](../skills/aeons-idea-workflow/SKILL.md)。下面只描述使用顺序，不另造一套评审标准。

| 环节 | 需要做的事 | 主要记录 |
| --- | --- | --- |
| 保留想法 | 先独立保存人的原始表达，再讨论 AI 扩展 | 原始文件、`draft.md`、冻结的 `vNNN.md` |
| 查证与阅读 | 找能改变判断的近邻与反证；PDF 需要转换时用 Marker | 共用论文库、来源与读取范围 |
| 版本评审 | 针对具体版本讨论重合点、替代解释、资源限制和下一步 | 绑定版本路径与 SHA256 的 review |
| 人的取舍与改版 | 记录实际采纳、拒绝或暂缓的建议，再按授权修改 | `decisions.md`、新版本与差异 |
| 最小 pilot | 先写假设、对照、指标与预算，再执行并保存实测结果 | 带版本/run ID 的计划、结果与日志 |
| 是否继续投入 | 阅读实测结果后，由研究者决定继续、修改或停止 | 人的决定与交接材料 |

文献转换见 [reading.md](reading.md)。idea 工作区结构、版本脚本、review / pilot / handoff 模板均以 skill 内的说明为准。LLM 的探索性讨论可以保存在项目 `sessions/` 中，但正式决定和实验结果应回到对应的记录文件。

最小起步指令：

```text
使用 aeons-idea-workflow。项目根目录是 /absolute/project。
我的原始想法在……。先读已有材料，保留原文，
围绕当前最不确定的问题继续讨论；本轮目标是……。
```

没有新证据时，不必反复生成完整 review。计划、接口测试与 AI 评分均不能写成 pilot 已支持研究主张。
